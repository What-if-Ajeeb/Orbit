# ORBIT Buddy character assets

Each Buddy species gets its own directory. All artwork is original, layered SVG
generated by `scripts/generate-buddy-assets.py`; there are no runtime recolors,
emoji, or shared generic silhouettes.

## Runtime contract

Every evolution SVG includes the same layer IDs so `RigCharacterAvatar` can
animate without species-specific renderer code:

- `body-group`, `head-group`, `accessory-group`, and `shadow`
- `eyes-open`, `eyes-closed`, and `eyes-thinking`
- `mouth-idle`, `mouth-happy`, `mouth-sad`, `mouth-angry`, `mouth-thinking`,
  `mouth-curious`, `mouth-speaking`, and `mouth-sleep`
- `expression-blush`, `expression-sweat`, and `expression-sparkle`
- anatomy groups listed in the species rig, such as `tail-group`,
  `wing-left-group`, or `trunk-group`

Parrot additionally ships `beak-closed` and `beak-open`; its rig maps those
groups in place of the mouth layers.

`expressions.svg` and `animations.svg` are reference/rig sheets. The runtime
expression layers are embedded in every base and evolution SVG.

## Files per species

| File | Purpose |
| --- | --- |
| `base.svg` | Stage 1 form |
| `evolution-stage2.svg` | Stage 2 form |
| `evolution-stage3.svg` | Stage 3 form |
| `evolution-<alt>.svg` | Species-specific special evolution |
| `shiny-form.svg` | Curated shiny palette + sparkle overlay |
| `expressions.svg` | Expression sheet used for QA/reference |
| `animations.svg` | Motion sheet used for QA/reference |

Form IDs come from `src/lib/buddy/species.ts`, and the generated asset maps in
`src/lib/buddy/characters/assets/` must match them exactly. There is no generic
`_mythical` form for the 15 rig species; only the documented alternate below.

## Regenerating

```bash
python3 scripts/generate-buddy-assets.py
```

The generator rewrites the 15 packs and their TypeScript source maps. Review the
diff before committing; runtime tests validate every form, expression state, and
appendage layer against `species.ts`.
